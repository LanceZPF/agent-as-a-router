# Docs Index

This folder documents two mostly-independent things living in one repository:

1. **ACRouter** — the Python research/reproduction package for the paper (routing algorithm,
   `CodeRouterBench`, benchmark scripts). Root [`README.md`](../README.md) is the entry point;
   [`HANDBOOK.md`](HANDBOOK.md) is the fuller version with maintainer notes and publishing
   commands.
2. **AgenticRouter** — the .NET 10 reproduction of the ACRouter proxy/router
   (`src/AgenticRouter/`) plus its Windows tray dashboard, `AgenticRouter.Gui`
   (`src/AgenticRouter.Gui/`). Everything else in this folder is about one of these two.

When a doc's claims and the actual code disagree, **the code wins**. Several docs below are
marked `(Proposed — not yet implemented)`; treat those as design intent, not current behavior.

## `gui/` — AgenticRouter.Gui (the tray dashboard)

Matches the real, implemented app: a **.NET MAUI Blazor Hybrid** project at
`src/AgenticRouter.Gui/` (Razor components in `Components/*.razor`, mock data in
`Models/DashboardData.cs`).

| File | What it covers |
|---|---|
| [`dashboard.md`](gui/dashboard.md) | Full prose spec of every tab, card, and interaction — the canonical reference for what the dashboard does today. |
| [`livestream-redesign-plan.md`](gui/livestream-redesign-plan.md) | Design log for the Live Stream tab's conversation/turn-centric revision: context, decisions, and the rationale for departures from earlier iterations. |
| [`backlog.md`](gui/backlog.md) | Not-yet-implemented work: live proxy integration and the smaller gaps that unblocks, plus deferred/optional items called out in the redesign plan. |

**Visual/brand authority:** [`design/`](design/) is a separate, tool-generated design system
(components, tokens, guideline cards, a `SKILL.md` for prototyping) derived from `dashboard.md`
and the app's compiled stylesheet. It is regenerated by its own tool — don't hand-edit its
structure or content beyond fixing a broken path. Treat it as authoritative for colors, type,
spacing, motion, and component conventions; `dashboard.md` is authoritative for tab *behavior*.

## Maintenance notes for future agents

- **Status tags matter.** If you implement something a `(Proposed — not implemented)` doc
  describes, remove that banner and update the doc to match what you actually built — don't leave
  the banner stale in the other direction either.
- **Before adding a new architecture/plan doc**, check whether it describes something that already
  has a doc in `gui/` or `router/`. This folder previously accumulated duplicate "plan update
  status report" docs (now deleted) that repeated the same content five ways; prefer editing the
  existing canonical doc over adding a new "summary of what I just did" file.
- **`design/` is off-limits for manual restructuring** — it's generated by a design-sync tool from
  `gui/dashboard.md` and the app's CSS/data. Fix a broken relative path if you move
  `gui/dashboard.md`, but don't reorganize its internals by hand.
